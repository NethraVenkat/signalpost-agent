# Signalpost

Signalpost researches Norwegian companies from official registries and bounded company-owned sources, verifies identity, and publishes evidence-linked facts, cited summaries and searchable offline profiles. Missing or incomplete information remains explicit. Deterministic template synthesis works without API keys and costs $0 in provider fees; no live model adapter is shipped.

## How it works

Hiring uses the bundled, org-number-keyed official NAV index for discovery,
then checks each nominated ad live. Rebuild it with
`python scripts/build_nav_index.py --no-seed-from-disk`; the maintenance build
has its own explicit limits and report, while evaluator runs retain the shared
1,850-request / 35-minute limit per 100 inputs. A stale or incomplete index is
reported and falls back to the bounded official feed; a name match never proves
an employer relationship.

Careers discovery follows only a current exact-number VERIFIED site's own
navigation/footer, including links to Webcruiter, Teamtailor, Jobylon, ReachMee,
Easycruit, Recman or Varbi. At most four linked pages share the existing company
and global counters, robots checks and politeness. Supported `JobPosting`
records need their own title and a current posting date/deadline or an explicit
open status attached to that title. Expired, undated and group-site postings
are withheld. Unsupported layouts, query-dependent ATS URLs and unproven
redirect chains remain discovery limitations; `run.refresh.careers` records
checked URLs and cutoffs separately from NAV coverage.

```mermaid
flowchart LR
    Input[Company numbers] --> Plan[Plan bounded source calls]
    Plan --> Tools[Registry, roles, branches, accounts, websites, NAV]
    Tools --> Verify[Identity firewall + evidence checks]
    Verify --> Publish[Publish or abstain]
    Publish --> Diff[Diff previous run]
    Diff --> Summary[Generate and validate cited synthesis]
    Summary --> Output[Validated envelopes + report + offline site]
```

Frozen bulk files are streamed without interrupting the input scan at the crawl deadline, retaining selected rows only. Preparation remains charged to total wall time; report key `bulk_preparation_seconds` records it. Missing CSV records use live lookup within the original crawl deadline; slow preparation never grants a fresh request window; neither source failure nor expiry invents identity facts.

The agent reserves output membership before requests, isolates company/section failures, and preserves every input record in order, including duplicates. It prefers the bulk registry snapshot, uses live fallback, and adds website identity proof, exact-company job advertisements and dated public activity by default. [Agent loop](docs/AGENT.md).

## Install and run

Python 3.12+ and [uv](https://docs.astral.sh/uv/) are required.

```sh
uv sync --frozen
uv run signalpost run --organisations batch.jsonl --bulk registry.csv --output envelopes.jsonl --profiles-output profiles.jsonl --report report.json --run-id signalpost-example --expected-count 100
```

The example assumes 100 input rows; set `--expected-count` to your actual batch membership. All seven evaluator flags are supported: `--organisations`, `--bulk`, `--output`, `--profiles-output`, `--report`, `--run-id`, `--expected-count`. Always inspect `counts_by_state`, section states, warnings and `site.state`; exit zero alone is not all-source success. Optional site rendering can be skipped for insufficient remaining time, with mandatory outputs preserved.

Input accepts JSONL organisation_number rows (extra keys ignored), numeric identifiers, a JSON list or organisation_numbers object, or plain lines, including BOM/CRLF and trailing blanks. Numbers remain strings; whitespace/BOM are normalized and mod-11 validated. The default preserves one envelope per input record in original order, including duplicates and invalid records; duplicates share research. `--deduplicate` explicitly emits unique identifiers only. Invalid identifiers retain failed envelopes without requests. Omit `--bulk` for live identity lookup; use `--no-websites`, `--no-hiring` or `--no-public-activity` to disable the corresponding enrichment. The old positive flags remain accepted for compatibility. Add `--previous prior.jsonl` for refresh.

## Evidence and safety

- The identity firewall checks exact company/parent identifiers. Guessed websites require exact organisation-number proof; registered domains have stricter documented corroboration rules. Same-name companies and group navigation do not alone establish ownership.
- Every published fact links a source URL/identifier, UTC retrieval time, stored-body SHA-256, locator, extractor version and a verbatim span of at most 300 characters. Unknown/failure placeholders never invent evidence.
- Availability is explicit: available, not_available, blocked, not_applicable, ambiguous or failed. Missing values are null; numeric zero is retained only when reported.
- Financial claims preserve the exact entity period, currency and unit reported by the source. No unit or scale is inferred. All earlier entity statements returned by the existing API response are retained; one additional official request lists years with available annual-accounts copies. That list is evidence-linked and feeds the newer-filing flag. Dimensionless ratios require the same statement and matching period, declared currency and unit-field value; matching absent units cancel without assigning scale. YoY additionally requires comparable consecutive annual periods, positive prior revenue, and matching units (or both absent from the same approved source schema). Absolute missing units stay visibly unknown.
- URL allowlists, DNS pinning, robots, redirect checks and per-source/global budgets constrain requests. Source bodies stay local; tokens are never stored in blobs or logs.
- Summary sentences cite supported claims. Numbers, dates, names, URLs and verbatim quotes are checked against those citations. Workplace, board and ad counts cite distinct underlying records and remain derived summary metadata, outside the source-fact claims list. Invalid sentences are dropped with recorded reasons.

[Identity resolution](docs/IDENTITY_RESOLUTION.md) explains publication rules. [Source policy and licences](docs/SOURCES.md) describes access constraints.

## Outputs and refresh

`out/envelopes.jsonl` contains validated company envelopes. Shapes are contract, reference or their union (default). The compact union profile restates values/evidence IDs; raw source bodies remain under `state/blobs/<sha256>`. `out/report.json` records membership, source states, request logs, runtime percentiles, shared/detail request attribution, output size, changes and cost.

Every envelope includes `run.synthesis` in contract/union output, mirrored at `profile.synthesis` in reference/union output. It covers activity, scale, leadership, changes and explicit unknowns. Norwegian registry text is quoted as reported; website descriptions are labelled company self-descriptions. Only the latest reported accounts are available, so financial growth is not inferred.

Company changes require successfully checked sections in both runs. Failed/blocked/ambiguous transitions are observations. Supported prior facts can be carried forward with original evidence; known inactive/expired ads are removed. [Schema](docs/DATA_SCHEMA.md), [refresh](docs/REFRESH.md).

Terminal states: an envelope is `submission_error` only for invalid input. A source that fails, is ambiguous or runs out of time keeps its explicit section state and error code (`failed`, `ambiguous`, `deadline`, `budget_exhausted`, `nav_consumer_stopped`); its module is `source_error` or `budget_exhausted` and the envelope stays `complete`, which describes processing and not full coverage. Registry identity for companies in the bulk CSV is built before any network work, so a deadline cannot remove it. The site is optional: if it cannot finish inside the remaining time budget it is skipped and the report records `site.state: skipped`.

Exit zero means output was written for all parsed input records, including explicit failures. Source, budget and site errors preserve that exit behavior. `--deduplicate` deliberately changes multiplicity. Unreadable input has unknown membership and an explicit warning. Check report states and verify output; exit zero does not by itself establish source success.

## Profile site

```sh
uv run signalpost site --input out/envelopes.jsonl --out site/ --title "Signalpost"
```

Open `site/index.html` directly or serve the directory with a static server. Search names or organisation numbers, filter coverage and municipality/industry, and compare two or three companies. Profiles include cited summaries, section states, financials, people, locations, hiring, public activity and changes. Source buttons show exact excerpts, hashes, retrieval dates and extraction provenance; all supporting records load from local per-company data files. Previously supported facts are marked explicitly.

`signalpost run` generates profiles in `<output directory>/site/` by default, including with only the seven evaluator flags. Use `--site-dir site/` to choose another directory or `--no-site` to disable it. The report records `site.state` as available, skipped, failed or disabled; deadlines can skip the site while preserving required JSON outputs. Site errors are recorded under `site` in the run report and preserve run output and exit behavior. Generation accepts contract/reference/union shapes, isolates malformed identifiers (no page; a notice lists them) and merges identical duplicate envelopes into one profile. Large companies render up to 48 initial Evidence Explorer rows (fewer when needed by the unchanged HTML size gate) and reveal the rest from the local data file, which keeps every profile page under the 250 KB gate without dropping a claim, and uses no network or extra dependency. Static CSS/JavaScript, a safely escaped local index script and `c/<orgnr>.data.js` evidence tables work under `file://`; untrusted text is escaped and only HTTP(S) fact links are clickable. Identical envelopes produce identical files. Use a new empty output directory for a different company population; generation does not delete older files.

## Models, APIs, licences and cost

Official Bronnoysund registry/accounts APIs, bounded company-site requests, the official NAV feed, GLEIF (CC0) and TED public procurement notices (EU reuse policy) supply facts. New-source terms, robots receipts and attribution limits are documented in docs/SOURCES.md. No source-site browser renderer or model API is used. Without optional search, provider cost is **$0 per batch**, per 100 companies and per configured 1,100-company batch, excluding compute/storage/network.

Optional website search is off without `BRAVE_SEARCH_API_KEY`, the same variable used by the starter kit's Brave connector. `SIGNALPOST_SEARCH_PROVIDER=brave` selects the shipped implementation; the provider interface also supports injected test adapters. Only companies lacking a proven site after registry/email/subunit/slug candidates are eligible. One logical query per company, up to five filtered result domains; results stay in memory and never become evidence. Existing fetch, robots, SSRF, politeness and exact-orgnr proof rules apply. Social, directory and known marketplace domains are excluded.

Controls: `--search-max-queries` defaults to the input-company count, `--search-max-cost-usd 5`, `--search-unit-price-usd 0.005`. The meter conservatively counts retries as billable queries; at most one retry, bounded timeout/backoff and all calls count against the existing global and per-company request budgets. No search is purchased unless request room remains for robots and a proof page. Price is **verify before use**: Brave publishes [$5 per 1,000 Web Search requests](https://brave.com/search/api/), so estimated cost is `$0.005 × queries`, with no assumed free credit. Verify official instructions and provider pricing before submission. No development key was supplied; only mocked search tests were run.

### AI usage

The optional model interface accepts only approved English sentence frames with claim placeholders. Values are substituted locally and validated; the model can reorder sentences while retaining template facts and unknowns. Inputs are bounded to 2,000 tokens, outputs to 500, with call/cost caps and a local cache. Errors or rejected output fall back to the template. Live adapters, verified model pricing and environment-based execution remain future work. `auto` currently uses templates; `llm` without an injected provider falls back explicitly. Environment names in `.env.example` are reserved, not an enabled integration.

## Limitations

Website recall measured 20/300 (6.667%) and 19/300 (6.333%) in the two audited samples with zero known errors in the reviewed publication population. NAV name discovery can miss unknown trading names; unusable names and caps remain explicitly incomplete. Live sources can change, historical carried-forward support is not fresh verification, and external evaluator/resource acceptance is not established. There is no live model adapter. [Limitations](docs/LIMITATIONS.md).

Raw profiles: `--profiles-output profiles.jsonl` preserves input-record order and duplicates, including invalid/failed rows with explicit states and null missing values. Module records use the reference field/status/source_type/source_class/source_url/retrieved_at/value/as_of/note/content_sha256/source_row_key/effective_at layout. `verified_claims` and `source_records` retain exact claim values and their provenance; no additional source facts are retrieved or inferred. Profiles are a separate output, not a replacement envelope shape. The kit scorer is invoked with `--profiles profiles.jsonl`.

Runner compatibility: `--organisations`, `--bulk`, `--output`, `--profiles-output`, `--report`, `--run-id` and `--expected-count` accept the kit runner's exact flag names. Existing invocations without `--profiles-output` keep writing envelopes and a report; add the flag for the two-file evaluator form above. `--envelope-shape contract` and `reference` remain optional overrides; union is default. ### Adaptive website scheduling (Stage A)

With the seven evaluator flags, pass 1 preserves registry homepage/email and the two strongest full-name spellings before branch/provider contacts; it also uses registered subunit websites/emails, any already verified live NAV employer homepage and remaining name variants. A NAV homepage is a nomination only: its saved active detail must match the exact company or a currently registered subunit; headers/index names never authorize publication.

After pass 1 and shared source processing finish, pass 2 ranks untried nominations by source strength (registry, subunit, verified NAV detail, then name/brand variants), preferring `.no` within a tier. It spends only the remaining global budget within the original deadline. Pass 1 stays at 8/13 HTTP and eight DNS nominations; A2 grants unfinished companies up to five additional HTTP slots and four additional DNS nominations in pass 2 (absolute maxima 13 website HTTP / 18 overall company slots / 12 DNS nominations). Lower configured caps still apply before the extension. All pass-2 work, including retries, shares the one extra allowance; there is no allowance per candidate. No counters, robots policy or vetoes reset. Once per strong registry/email/subunit/NAV candidate, pass 2 may evict only cached timeout/connect/5xx failures for a fresh retry; successful pages, NXDOMAIN and refusals remain cached. A shared candidate receives at most one fresh retry across companies. Use `--no-adaptive-extra-budget` to retain the earlier non-extended second pass. Exact-number proof ends work for that company; cached pages are re-scored for the current entity. Exhausted allowances stay explicit, so a second pass may gain zero websites.

`report.adaptive_websites` records pass requests, websites gained and per-company states; each request log entry has a pass label. Planning skips at a capacity limit retain pass 1's completed checked scope, with explicit pass-2 states/errors; attempted checks keep their actual source/budget states. `--no-adaptive-websites` (or `Config(adaptive_websites=False)`) keeps single-pass discovery. A newly verified second-pass site can feed public activity without dropping retained registry activity. No paid search or model is enabled by the scheduler.

### Cited briefing contract (Stage S)

Every template briefing contains activity, change, unknowns, financial context and a partner-screening takeaway. Each sentence cites supported publisher facts, typed run-status observations, or both. On a first run the change sentence says so and cites the latest supported dated registry observation; refresh comparisons describe only the checked scope. Run-status citations explain source states and report limits, separately from publisher receipts. They never invent a publisher excerpt or hash for a failed check. Both `run.synthesis` and `profile.synthesis` carry the same contract, checked again by `scripts/verify_output.py`. Optional model output that loses a required element falls back to the verified template.

The newer-filing flag compares the registry accounts year with the figures year; it does not claim to detect same-year refilings. Financial calculations are explicitly labelled derived and are descriptive, not forecasts or suitability assessments. Missing comparable inputs produce a cited limitation. Verification checks source JSON pointers, exact entity ownership, periods, units and arithmetic independently of sentence generation. Stage S measurements and browser evidence are in `reports/r5/stageS/`.
