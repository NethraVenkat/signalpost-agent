## Correction found during the release checks
The CLI passes every option with its own argparse default, so earlier changes to `Config` defaults (website request cap 8/13, deadline fraction 0.9) never applied to a CLI run. Every gate run used 6/9 and 0.85. The `Config` defaults are back to the CLI values and a test now fails if they differ. The 8/13 budget was therefore never measured and is withdrawn (Phase 2). The standard proof pages (P1c) run under the shipped cap of 6. No CLI behaviour changed in the correction commit.

For each, the stored page(s) cited from the company's own site were opened and checked for the exact organisation number (spaced, dotted or unspaced) or for the official domain declared in the registry (website or e-mail domain). Full log: [spotcheck-websites-v1.0.0.txt](spotcheck-websites-v1.0.0.txt). These are the pages as retrieved during the run, not a second live fetch.

- **28 of 30 conform**: the exact number is on the cited page (23, of which 10 also match the registry-declared website or e-mail domain) or, for 5 claims verified on name/address/domain signals, the site's registrable domain equals the registry-declared website or e-mail domain with the number not on the page.
- **JBF Forsikring AS (940590698), new — accepted**: `jbf.no` is a group site whose footer names both entities with their numbers (`982 719 445 (JBF Sparebank AS) og 940 590 698 (JBF Forsikring AS)`); the registry declares `www.jbf.no` as this company's website.
- **FILMTEK AS (988330752), existing since ac60875 — does not meet the stated test and needs a decision**: the claim is `https://www.audioped.no`, verified through a registered branch. The page footer says `AudioPed AS · Org.nr 933 248 380`; the registry lists 933248380 (`AUDIOPEDAGOG THERESE WIDERØE`) as an *underenhet* of FILMTEK AS (`overordnetEnhet` 988330752, registered e-mail `post@audioped.no`). It is therefore a registry-attested branch of the same legal entity, not an unrelated company, but the page carries neither the parent's number nor the registry-declared company domain (`filmtek.no`, which loaded and scored HIGH), and the claim has `relationship_note: null`. This follows the shipped sub-unit proof rule; I did not change claim behaviour at the freeze.

## CI failure on f4958e2 and 59f72d8 (fixed in c7118e3)
GitHub Actions `tests` failed on both commits with one failing test, `tests/test_finalisation_reserve.py::test_small_budget_drops_the_site_reserve_but_still_crawls`: `assert 15.000000000000007 <= 15`. The test subtracted two `time.monotonic()` readings and compared the difference exactly with the 15 s it was built from. On a freshly booted Linux runner the clock is about 40–60 s, where floats are spaced 7e-15 apart, so the difference is occasionally off by one ulp; it never failed on Windows. Reproduced locally with a clock of 63.86063473633481 (about 5% of values in 32–64 s). The same code passed on 61fbb51. It was a test bug, not a product bug; the test now uses a 1e-6 tolerance and a parametrised regression covers several clock values. No production code changed. Full suite: 463 passed on Python 3.12.15 and on Python 3.14; real Linux could not be run locally (no WSL or Docker), so the Linux confirmation is the GitHub Actions run.
