# G3: licensed official state-aid bulk extract

The official [Støtteregisteret interface](https://stotte.brreg.no/nb/oppslag/stoettetildeling)
advertises the complete [CSV export](https://stotte.brreg.no/nb/oppslag/stoettetildeling/totalbestand/csv).
Brreg's [dataset licence statement](https://www.brreg.no/bruke-data-fra-bronnoysundregistrene/datasett-og-api/)
links [NLOD 2.0](https://data.norge.no/nlod/no/2.0). Attribution:
contains data licensed under NLOD 2.0 provided by Brønnøysundregistrene.
This project selected non-personal columns and a three-year award window;
it does not imply publisher endorsement.

We downloaded the official CSV ourselves. The response is UTF-16LE without BOM,
semicolon-delimited, 341,060,138 bytes, SHA-256
`1742308dfbc97e7b68e1d46bed91eda7c2400092ecf0b16e554b242707db5a55`.
[Build receipt](G3-build.json) records its retrieval time, exact selected columns,
and the output hash. No competitor code, data, extract or saved response was used.
The 6,982,418-byte bundled extract contains 339,417 eligible source rows for
51,200 recipients; it retains their original source row numbers and verbatim
selected values. Birth dates and recipient names are excluded.

Only the registered recipient's exact valid org number attributes an award.
The separately published specified-recipient org number is retained as a distinct
field; award amounts are not reallocated to that organisation. Registered status,
award type, granting organisation, award ID, award date and the rolling three-year
window are checked. Amounts and intervals retain their source currency; unsupported
number formats are withheld. No name, parent, unproved subunit, or website expands
recipient scope. Duplicate award IDs publish once.

At runtime this is an explicitly dated snapshot, not a fresh award search. Each
claim stores the exact committed extract record bytes in the evidence blob store,
with source URL, retrieval time, hash and scalar pointers. The saved-output checker
requires that record to exist in this bundle for the exact org number and
re-derives every published value and field ID. The original CSV hash and row
number preserve the extraction lineage. The retained full CSV is local working
material, not tracked; reproducing the historical CSV byte hash requires that
retained download, while the committed extract and checks work without network.

The separate API origin remains fail closed after its robots retries. Production
runs send no request to it and no bulk download request. The publisher web robots
route redirects once to a 200 HTML page with no parsed robots groups; see
[G3-access.json](G3-access.json). This implementation uses the explicitly licensed
bulk route permitted by the task, not an exception for that unavailable API.

Rebuild from our own retained download (its hash must match the receipt for an
exact historical rebuild):

```sh
uv run python scripts/build_state_aid_snapshot.py --csv out/r5-gaps/state-aid.csv --out src/signalpost/data/state_aid.json.gz --retrieved-at 2026-11-19T15:51:59.2776852Z --build-day 2026-11-19
```

Twenty focused tests use three saved real extract rows: an exact amount, a
standard-cohort recipient, and a registered interval. They cover identity and
status rejection, dates, number formats, deterministic extraction, no API request,
evidence re-derivation and claim tampering.

Final combined regression suite: **1,438 passed in 1,014.72 seconds**.
This includes the complete final G2 display/index safeguards and all G3 tests.
