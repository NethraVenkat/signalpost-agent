# G1: signature and prokura access check

Baseline: `45afc2b`, with hash-only documentation follow-up `528e05a`.

The permitted competitor reports identify the first-party public lookup
`https://data.brreg.no/fullmakt/enheter/{orgnr}/{signatur|prokura}`.
Brreg's [first-party API documentation](https://data.brreg.no/fullmakt/docs/index.html)
and [access description](https://www.brreg.no/bruke-data-fra-bronnoysundregistrene/data-om-signatur-og-prokura-for-virksomheter/)
confirm an unauthenticated open-data variant, distinct from the restricted national-ID service.
Brreg states its datasets use [NLOD](https://www.brreg.no/bruke-data-fra-bronnoysundregistrene/datasett-og-api/).
No competitor code or data was used.

The canonical origin robots URL failed with `RemoteProtocolError` on all three
attempts, including the production user-agent, with 5/20-second backoff.
The Windows HTTP client independently reported a connection reset. Documentation
was reachable, but that does not establish an allow decision for company data.
[G1-preflight.json](G1-preflight.json) records the result. No authority response was obtained. The local HTTP probe stopped at robots; a separate web-tool lookup returned not accessible and supplied no response data.

G1 is blocked by unavailable robots, not by a finding that this API is prohibited.
No signature/prokura publisher or real-response fixture has been fabricated.
Implementation and its required real-response tests remain pending a successful
robots preflight. This is not a completed recall improvement.

Regression check: the 1,411 existing tests passed in 1,095.48 seconds.
This does not substitute for the pending real authority-response tests or imply
that signature/prokura was implemented. [Test output](G1-tests.txt).
